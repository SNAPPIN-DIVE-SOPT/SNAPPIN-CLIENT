# Git Convention Checker

이 프로젝트(snappin-client)의 브랜치명·커밋 메시지·PR/이슈 제목 형식을 확인하거나 만들어줍니다.

## 기준 문서

`references/git-conventions.md`를 읽으세요. 브랜치명, 커밋 메시지, PR/이슈 제목 패턴과 타입-이모지 매핑 표가 있습니다.

## 하는 일

1. **현재 상태 확인**
   - `git rev-parse --abbrev-ref HEAD`로 현재 브랜치명 확인
   - `git log`로 이번 작업에서 쌓인 커밋 메시지들 확인 (베이스 브랜치와의 `git merge-base` 이후 커밋만)

2. **패턴 검사**
   - 브랜치명이 `<type>/#이슈번호/작업내용` 형식인지
   - 각 커밋 메시지가 `<type>(범위): 설명` 형식인지
   - `<type>`이 매핑 표에 있는 타입(`init`/`fix`/`style`/`feat`/`refactor`/`docs`) 중 하나인지

3. **결과 안내**
   - 형식에 맞으면 ✅, 어긋나면 ❌와 함께 무엇이 잘못됐는지, 올바른 형식이 뭔지 제시
   - 사용자가 PR/이슈 제목을 요청했다면 브랜치명·커밋 내용을 바탕으로 매핑 표에 맞는 이모지+타입을 골라 제목을 제안

4. **수정 여부 확인 후 적용** — 어긋난 항목이 있으면, 결과를 보여준 다음 고쳐도 될지 물어본다. 승인하면 다음과 같이 고친다:
   - 브랜치명: `git branch -m <새이름>`. 이미 원격에 push된 브랜치라면 원격 브랜치명도 같이 바뀐다는 점과 그 영향을 먼저 알려주고 진행한다.
   - 커밋 메시지: 아직 push 안 된 커밋이면 `git commit --amend`(가장 최근 커밋) 또는 인터랙티브 rebase로 고친다. 이미 push된 커밋이면 히스토리를 다시 쓰는 것이므로(강제 푸시 필요) 더 명확히 확인받고 진행한다.
   - PR/이슈 제목: 실제로 존재하는 PR/이슈라면 `gh pr edit --title`/`gh issue edit --title`로 변경한다. 공개 콘텐츠 수정이니 사용자 승인 없이는 실행하지 않는다.
   승인 전에는 아무것도 바꾸지 않는다.

## 출력 형식

```markdown
## Git 컨벤션 체크

- 브랜치명: ✅ `feat/#13/input-develop`  (또는 ❌ 사유 + 올바른 형식 제안)
- 커밋 메시지: ✅ 전부 형식 준수 (또는 ❌ 어긋난 커밋과 사유 나열)
- PR 제목 제안: 🎀 Feat(input): #13 검색창 컴포넌트 개발
```
