# Web Design Guidelines

Vercel이 공개한 [web-interface-guidelines](https://github.com/vercel-labs/web-interface-guidelines) 체크리스트를 기준으로 UI 코드를 점검한다. 이 저장소는 계속 업데이트되므로, **정적으로 저장해두지 않고 매번 최신 버전을 받아온다.**

## 절차

1. `https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md`를 fetch해서 최신 가이드라인을 받는다.
2. 사용자가 지정한 파일, 또는 지정하지 않았다면 어떤 파일/패턴을 리뷰할지 사용자에게 먼저 물어본다.
3. 받아온 가이드라인의 모든 규칙에 대해 대상 파일들을 점검한다.
4. 가이드라인 문서에 명시된 출력 형식(`file:line` 표기, 파일별로 그룹화, 간결하게 — 수정 방법이 자명하지 않을 때만 설명 추가)을 그대로 따른다.

가이드라인 문서 자체가 출력 형식과 우선순위를 지정하고 있으니, 이 문서에서 규칙을 다시 베끼거나 요약하지 말고 fetch한 원문 기준을 그대로 따른다 — 원본이 바뀌면 자동으로 최신 기준을 따르게 하기 위함이다.

## 이 프로젝트에서 참고할 점

- `@snappin/design-system`의 컴포넌트를 쓰고 있다면 시각적 스타일(색상, 여백, 타이포그래피 토큰)은 이미 일관성이 보장되므로 중복 지적하지 않는다. 이 스킬은 그 위에서 접근성·상호작용·키보드 내비게이션처럼 컴포넌트 라이브러리가 자동으로 보장해주지 않는 부분에 집중한다.
- 가이드라인과 이 프로젝트의 팀 컨벤션(`code-convention-reviewer` 스킬)이 충돌하면(예: 특정 HTML 속성 표기 방식), 팀 컨벤션을 우선하고 그 사실을 리뷰 결과에 짧게 남긴다.
